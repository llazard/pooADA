La POO, c'est quoi ? Pourquoi ?

La POO, c'est quoi ?

La POO, programmation orientée objet, organise le code en s'inspirant du monde réel : chaque entité du monde réel devient un objet dans le programme.

  • Les attributs : les caractéristiques de l'objet. Un nom, un âge, un pelage…
  • Les méthodes : les actions de l'objet. Se déplacer, manger, se présenter…
  • La classe : le moule qui sert à fabriquer les objets. Elle définit leurs attributs et leurs méthodes, mais ce n'est pas encore un objet.

La classe est le moule, l'objet est ce qui sort du moule.

Une classe, des objets

La classe Animal se définit une fois. On en crée ensuite autant d'objets qu'on veut : Rex, Félix, Nemo… Chaque objet a ses propres valeurs, mais tous suivent le même modèle.

Pourquoi la POO ?

Sans POO, comme vous l'avez souvent fait en JavaScript : une variable par caractéristique et par entité.

  • nameAnimal1, ageAnimal1, coatAnimal1
  • nameAnimal2, ageAnimal2, coatAnimal2
  • …

50 animaux, 10 caractéristiques chacun : 500 variables. De la duplication, et des erreurs.

Avec la POO :

  • Organisation : chaque concept regroupé dans une classe.
  • Réutilisabilité : on écrit une fois, on réutilise partout.
  • Lisibilité : le code ressemble au monde réel.
  • Maintenabilité : une modification se fait à un seul endroit.

Comment l'utiliser ?

Du général au spécifique

Deux sortes de classes

  • Les classes génériques : elles définissent ce que plusieurs classes ont en commun. On ne crée pas d'objet à partir d'elles. Ce sont les classes dont on hérite, et les interfaces.
  • Les classes concrètes : elles rentrent dans le détail. Ce sont elles qu'on utilise pour créer des objets.

On part d'une idée générale commune, pour aller vers le plus spécifique.

Un exemple : les animaux

Animal regroupe ce que tous les animaux ont en commun : un pelage, un cri, un nombre de pattes, un habitat, un régime alimentaire. Mais impossible de tout remplir sans en savoir plus.

On affine :

  • Mammifère : il se reproduit en vivipare.
  • Poisson : il a des écailles, il vit dans l'eau, il nage.
  • Oiseau : il a des plumes, il vole.

Jusqu'aux classes concrètes

  • Chien : un mammifère terrestre, qui aboie.
  • Saumon : un poisson, muet, carnivore.
  • Poule : un oiseau, qui caquette… et qui marche !

Tout est enfin défini : je peux créer mes premiers objets.

Les piliers de la POO

Encapsulation, abstraction, héritage, polymorphisme

Les 4 piliers en un coup d'œil

  • Encapsulation : regrouper les attributs et les méthodes dans une classe, en restreignant l'accès direct aux données internes.
  • Abstraction : exposer l'essentiel d'un objet, et cacher son fonctionnement interne.
  • Héritage : une classe fille réutilise ce que sa classe mère expose, et peut compléter ou redéfinir ses comportements.
  • Polymorphisme : un même appel peut produire des comportements différents, selon l'objet ou selon les paramètres.

L'encapsulation

Regrouper les attributs et les méthodes d'un objet dans une classe, en restreignant l'accès direct à ses données internes.

  1. Le constructeur contrôle la création : il vérifie que les valeurs de départ sont valides, avant même que l'objet existe. Un âge négatif est refusé.
  2. private maintient la protection après la création : sans lui, n'importe quel code pourrait modifier l'âge et contourner le constructeur.
  3. Les getters et setters filtrent les accès : ils peuvent valider, transformer, ou ne pas exister. Ce sont des points de contrôle, pas de simples relais.

L'encapsulation garantit que l'objet reste cohérent tout au long de sa vie.

L'abstraction

Trois mots qui se ressemblent et qu'on confond facilement :

  • L'abstraction, le pilier : une idée générale. Exposer l'essentiel, cacher le détail. C'est un principe, pas une syntaxe.
  • La classe abstraite : un outil de ce principe. Animal est un concept, pas une réalité : on ne crée pas un « animal générique ». Elle sert de base commune, incomplète par nature.
  • La méthode abstraite : une méthode sans corps. Chaque animal a un cri, mais Animal ne dit pas lequel : chaque fille doit écrire le sien. C'est un contrat.

L'héritage

Une classe fille réutilise ce que sa classe mère expose, et peut compléter ou redéfinir ses comportements. En Java, avec le mot-clé extends.

Le Chat hérite de Mammifère, qui hérite d'Animal : il a déjà un pelage, quatre pattes, il vit sur terre et il est vivipare. Il n'a plus qu'à dire qu'il miaule.

L'héritage, ce qu'on oublie souvent

  • Le lien de famille : extends dit « le Chat est un Mammifère ».
  • Les constructeurs ne s'héritent pas : la fille doit transmettre à la mère ce dont elle a besoin, en appelant son constructeur avec super(...).
  • Les attributs privés de la mère existent bien dans l'objet de la fille, mais elle n'y accède que par les méthodes de la mère. L'héritage et l'encapsulation fonctionnent ensemble.
  • La fille peut ajouter ses propres attributs : le Chien a un nom, qui n'existe pas dans Animal.

Le polymorphisme

Un même nom de méthode peut produire des comportements différents. Deux formes :

  • La redéfinition : la fille réécrit une méthode héritée, avec la même signature. L'Oiseau se déplace en volant, la Poule redéfinit le déplacement : elle marche. Java choisit à l'exécution, selon l'objet réel.
  • La surcharge : plusieurs méthodes du même nom, avec des paramètres différents. Manger, manger un aliment, manger une quantité d'un aliment. Java choisit selon les paramètres donnés.

L'héritage donne un comportement par défaut, le polymorphisme permet de l'adapter. Il en existe d'autres formes : celles-ci sont les deux que vous utiliserez tous les jours.

L'interface

Une interface est un contrat : une liste de méthodes qu'une classe s'engage à écrire, sans dire comment.

Le Saumon, la Baleine, le Chien et le Canard savent tous nager, sans être de la même famille. Une interface « Nageur » le dit, quelle que soit leur classe mère.

Une classe n'a qu'une mère, mais peut suivre plusieurs interfaces.

Le vrai critère de maîtrise

Si vous savez expliquer pourquoi votre code fonctionne, vous connaissez le concept.

  • Nommer, pour communiquer : dire « ici, j'ai utilisé le polymorphisme » en revue de code ou en entretien.
  • Comprendre, pour concevoir : choisir le bon outil pour le bon problème.
  • Expliquer, pour maîtriser : justifier chaque ligne à un pair.

À retenir

  • Une classe est un moule : on la définit une fois, on en crée autant d'objets qu'on veut.
  • Des classes génériques qui définissent, des classes concrètes qui rentrent dans le détail.
  • L'héritage dit « est un », l'interface dit « sait faire ».
  • Le polymorphisme : la redéfinition à l'exécution, la surcharge selon les paramètres.
  • La classe abstraite est un outil de l'abstraction, l'interface en est un autre.
