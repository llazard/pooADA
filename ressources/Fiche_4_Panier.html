Exercice 4 : le panier

Le contexte : une boutique ajoute au panier un produit, plusieurs exemplaires, ou un article saisi à la main. Trois façons de faire, un seul nom de méthode : add.

Ce qui est travaillé : surcharger une méthode et un constructeur (this(...)), voir que le compilateur choisit selon les paramètres, et voir les cas où la surcharge est refusée.

Question 0, avec la formatrice

Copiez les classes et le Main, et lancez le.

public class Product {
    private final String name;
    private final int price; // en euros
    public Product(String name, int price) {
        this.name = name;
        this.price = price;
    }
    public String getName() { return name; }
    public int getPrice() { return price; }
}
import java.util.ArrayList;
import java.util.List;
public class Cart {
    private final List<Product> products = new ArrayList<>();
    public void add(Product product) { products.add(product); }
    public int total() {
        int total = 0;
        for (Product product : products) {
            total += product.getPrice();
        }
        return total;
    }
}
Cart cart = new Cart();
cart.add(new Product("Carnet", 4));
System.out.println("Total : " + cart.total() + " €");

La consigne

Après chaque méthode, complétez le Main et relancez.

  1. Deux constructeurs. Ajoutez à Product une catégorie, avec son getter getCategory(), et deux constructeurs : (name, price, category), et (name, price) qui appelle le premier avec this(name, price, "divers"). Dans le Main, créez un carnet à 4 € de catégorie papeterie, et un stylo à 2 € sans catégorie. Affichez la catégorie de chacun : qu'observez-vous ?
  2. Plusieurs exemplaires. Ajoutez dans Cart la méthode add(Product product, int quantity), qui réutilise add(Product). Dans le Main, mettez le carnet et trois stylos dans le panier : le total est de 10 €.
  3. Un article saisi à la main. Ajoutez add(String name, int price), qui crée le produit et réutilise add(Product). Ajoutez une gomme à 1 € : le total passe à 11 €.
  4. Une remise. Ajoutez total(int discountPercent), qui réutilise total(). Avec 10 % de remise, le panier coûte 9.9 €.
  5. Le total d'une catégorie. Ajoutez total(String category), qui renvoie le total des seuls produits de cette catégorie. Le panier contient 4 € de papeterie, et 7 € de divers.

Astuce : dans un constructeur, this(...) appelle un autre constructeur de la même classe. Le constructeur sans catégorie ne recopie pas les affectations : il passe la main au constructeur complet, avec la catégorie par défaut, « divers ».

reflexion.md :

  • Le stylo a la catégorie « divers », alors que vous ne l'avez pas donnée. Quel constructeur Java a-t-il appelé, et comment l'a-t-il choisi ?
  • Vos méthodes add portent toutes le même nom. Quand vous écrivez cart.add(...), comment Java sait-il laquelle appeler ?
  • total(int discountPercent) et total(String category) ont toutes deux un seul paramètre. Pourquoi Java accepte-t-il les deux ? Laquelle appelle cart.total(10), et laquelle cart.total("papeterie") ?

Étape 2 : quand la surcharge ne marche pas

La surcharge a ses limites. Testez-en deux, et supprimez à chaque fois ce que vous avez ajouté.

  1. Mêmes types de paramètres. La boutique lance un code promo : avec le code « BIENVENUE », le panier coûte 5 € de moins ; avec un autre code, le total ne change pas. À côté de total(String category), ajoutez total(String promoCode), et lancez. Lisez le message du compilateur.
  2. Seul le type de retour change. Le total avec remise renvoie un double : pourquoi pas le total simple aussi ? À côté de int total(), ajoutez un second total(), sans paramètre, qui renvoie un double, et lancez. Lisez le message du compilateur.

reflexion.md :

  • Avec total(String promoCode), que dit le compilateur ? Dans quel cas peut-on avoir deux méthodes du même nom ?
  • Les deux total() ne renvoient pas le même type, et Java les refuse quand même. Que dit le compilateur ? Imaginez l'appel cart.total(); : quelle version Java devrait-il choisir, et comment le saurait-il ?

Partie optionnelle

Ajoutez add(Product... products) : on peut lui passer autant de produits qu'on veut, séparés par des virgules. C'est ce qu'on appelle les « varargs ».
