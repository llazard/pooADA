Exercice 3, optionnel : recruter un héros

Le contexte : l'écran du jeu veut recruter un nouveau héros. Il envoie POST /heroes, avec le héros en JSON dans le corps de la requête.

Ce qui est travaillé : un second verbe sur le même chemin, lire le corps d'une requête, et répondre 201.

Question 0

Dans Thunder Client, envoyez POST http://localhost:8080/heroes, avec dans l'onglet Body, en JSON : {"name":"Gandalf","role":"mage","level":20}. Réponse : la liste des héros, code 200. Votre contrôleur ne regarde pas encore le verbe : il répond à un POST comme à un GET.

Créez ensuite NewHero dans le paquet rpg.model : le héros tel que le client l'envoie, sans id.

package rpg.model;

// Exercice 3 : le héros à recruter, tel que le client l'envoie. Pas d'id : c'est le
// repository qui le donne.
public class NewHero {
    private final String name;
    private final String role;
    private final int level;

    public NewHero(String name, String role, int level) {
        this.name = name;
        this.role = role;
        this.level = level;
    }

    public String getName() { return name; }
    public String getRole() { return role; }
    public int getLevel() { return level; }
}

La consigne

  1. Dans HeroRepository, écrivez create(String name, String role, int level). C'est le repository qui donne l'id, à partir de 7, comme le ferait une base de données.
  2. Dans HeroService, ajoutez create, qui passe la main au repository.
  3. Dans le contrôleur, quand exchange.getRequestMethod() vaut "POST", lisez le corps avec Json.read(exchange, NewHero.class) : Jackson construit le NewHero. Attendu : {"id":7,"name":"Gandalf","role":"mage","level":20}, code 201.
  4. Sans name dans le corps, répondez 400 avec {"error":"Le champ name est obligatoire"}.
  5. GET /heroes?role=mage : Gandalf est là. Arrêtez le serveur, relancez, appelez à nouveau. Où est passé Gandalf ?

Pour explorer : les codes 200, 201 et 400 sur MDN, https://developer.mozilla.org/fr/docs/Web/HTTP/Status
