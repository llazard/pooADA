Exercice 0 : la route de santé

Le contexte : vous refaites seul·es ce que nous venons de faire ensemble. La route de santé est la première qu'on appelle quand quelque chose ne marche pas : si elle répond, le serveur tourne, et le problème est ailleurs.

Ce qui est travaillé : passer d'un programme qui se termine à un serveur qui écoute, ajouter une bibliothèque au projet, écrire un premier contrôleur, et le brancher sur une route.

Question 0, avec la formatrice

Dans IntelliJ, créez un projet Maven rpg-api, et lancez le Main généré. Il affiche, puis s'arrête : un programme qui se termine.

Jackson est une bibliothèque qui permet la conversion en JSON. Toute nouvelle bibliothèque doit être ajoutée dans le pom.xml pour pouvoir être utilisée dans le code.

<dependencies>
    <dependency>
        <groupId>tools.jackson.core</groupId>
        <artifactId>jackson-databind</artifactId>
        <version>3.1.5</version>
    </dependency>
</dependencies>

Copiez enfin Json dans un paquet rpg.controller. Elle est fournie : cette classe sert de convertisseur JSON, et toutes vos réponses passeront par elle. Vous pouvez la copier coller sans vraiment chercher à comprendre comment elle marche : c'est une aide pour faciliter l'écriture d'une API sans framework, et vous n'en aurez plus besoin après.

package rpg.controller;

import com.sun.net.httpserver.HttpExchange;
import tools.jackson.databind.ObjectMapper;

import java.io.IOException;
import java.io.OutputStream;

// Fourni : toutes les réponses passent par ici. Jackson transforme l'objet en JSON, puis
// send écrit l'en-tête Content-Type, le code, et le corps.
public class Json {
    private static final ObjectMapper mapper = new ObjectMapper();

    public static void send(HttpExchange exchange, int status, Object body) throws IOException {
        byte[] bytes = mapper.writeValueAsBytes(body);
        exchange.getResponseHeaders().set("Content-Type", "application/json; charset=utf-8");
        exchange.sendResponseHeaders(status, bytes.length);
        try (OutputStream output = exchange.getResponseBody()) {
            output.write(bytes);
        }
    }
}

Astuce : avant de relancer Main, arrêtez le serveur précédent avec le carré rouge d'IntelliJ. Sinon : BindException: Address already in use, le port 8080 est déjà pris.

La consigne

  1. Dans Main, créez un serveur sur le port 8080, et démarrez le. Lancez : main se termine, mais le carré rouge reste allumé. Le serveur attend.
  2. Dans Thunder Client, ou directement dans votre navigateur, appelez GET http://localhost:8080/health : 404, « No context found for request ». Le serveur répond, mais aucune route ne porte ce chemin. On va donc ajouter notre healthcheck.
  3. Le contrôleur : dans le paquet rpg.controller, créez HealthController, qui implémente HttpHandler et répond ok, comme on vient de le voir en cours.
  4. Main : ajoutez votre chemin /health à votre serveur.
  5. Testez à nouveau http://localhost:8080/health : {"status":"ok"}, code 200.
