Exercice 2 : le service et les filtres

Le contexte : l'écran du jeu veut maintenant trier les héros : seulement les mages, ou celui dont on tape le nom. Chercher parmi les héros, c'est du métier, et le contrôleur ne s'occupe que de HTTP. Une couche arrive entre les deux : le service.

Ce qui est travaillé : ajouter une couche sans rien changer pour qui appelle l'API, lire un filtre dans l'adresse, placer la règle métier dans le service, et la tester sans lancer le serveur.

Le but : taper la requête dans le navigateur, http://localhost:8080/heroes?role=mage, et voir les mages. Le contrôleur s'écrit comme celui de la route de santé du cours, /health?name=Lucie.

Question 0, avec la formatrice

Créez le service dans le paquet rpg.service. Pour l'instant, il ne fait que passer la main au repository.

package rpg.service;

import rpg.model.Hero;
import rpg.repository.HeroRepository;

import java.util.ArrayList;
import java.util.List;

// Le métier : ce qu'on cherche parmi les héros. Ni HTTP ni JSON ici.
public class HeroService {
    private final HeroRepository heroRepository;

    public HeroService(HeroRepository heroRepository) {
        this.heroRepository = heroRepository;
    }

    public List<Hero> findAll() {
        return heroRepository.findAll();
    }
}

Dans HeroController, remplacez HeroRepository par HeroService. Dans Main, assemblez les couches :

HeroRepository heroRepository = new HeroRepository();
HeroService heroService = new HeroService(heroRepository);
server.createContext("/heroes", new HeroController(heroService));

Relancez : GET /heroes répond exactement comme avant.

La consigne

  1. Le service : dans HeroService, écrivez findByRole(String role). findByRole filtre les héros, et ne retourne que ceux dont le rôle correspond au rôle reçu en paramètre, sans tenir compte des majuscules (equalsIgnoreCase).
  2. Le contrôleur : dans handle, lisez le filtre, comme pour /health?name=Lucie. exchange.getRequestURI().getQuery() renvoie "role=mage", ou null quand il n'y a pas de filtre. null : rien ne change, service.findAll(). Sinon, query.split("=") donne ["role", "mage"] : si le nom est role, répondez service.findByRole(...) avec la valeur. Dans le navigateur, http://localhost:8080/heroes?role=mage : Merlin et Morgane. Puis ?role=necromancer : [], code 200. Aucun héros, ce n'est pas une erreur.
  3. Le service : écrivez findByName(String text), les héros dont le nom contient le texte, sans tenir compte des majuscules.
  4. Le contrôleur : un else if de plus, pour le nom name. ?name=merl : Merlin.
  5. Le contrôleur : le dernier else, un filtre inconnu. ?color=red répond 400 avec {"error":"Filtre inconnu : color"}, écrit par Map.of("error", …).
  6. Créez HeroServiceTest, dans src/test/java, paquet rpg.service, avec trois tests : les deux mages, le type inconnu qui renvoie une liste vide, et "MERL" qui trouve Merlin. Lancez les sans démarrer le serveur.

Partie optionnelle : un héros et son type

Deux routes : d'abord la description d'un type, avec un filtre, GET /roles?name=mage. Puis un héros avec la description de son type, GET /heroes/Merlin.

  1. Le repository : dans RoleRepository, ajoutez findByName(String name), le type qui porte ce nom, ou null.
  2. Le contrôleur : dans RoleController, lisez le filtre comme dans HeroController. GET /roles?name=mage : {"name":"mage","description":"Lance des sorts puissants, mais reste fragile"}. Et ?name=necromancer répond 404 avec {"error":"Type necromancer introuvable"}.
  3. Le modèle : créez HeroDetail dans rpg.model, les trois champs du héros et la description de son type. Un getter pour chacun : Jackson écrit un champ par getter.
  4. Le service : il reçoit aussi le RoleRepository dans son constructeur. findDetail(String name) reprend votre findByName, et ne garde que le premier héros trouvé, get(0). Puis il cherche son type avec le findByName du RoleRepository. Aucun héros : null.
  5. Le contrôleur : path.split("/") donne ["", "heroes", "Merlin"], trois morceaux, c'est un nom. GET /heroes/Merlin : {"name":"Merlin","role":"mage","level":18,"description":"Lance des sorts puissants, mais reste fragile"}. Et GET /heroes/Bilbo répond 404 avec {"error":"Héros Bilbo introuvable"}.
