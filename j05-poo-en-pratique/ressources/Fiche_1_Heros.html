Exercice 1 : l'équipe de héros

Le contexte : un jeu de rôle réunit des héros très différents. Chacun attaque à sa façon, mais l'équipe doit pouvoir les faire agir tous ensemble, sans savoir qui est qui : c'est ce que permet une interface.

Ce qui est travaillé : déclarer une interface, l'implémenter dans des classes qui la codent chacune à leur façon, manipuler des objets par le type de l'interface, faire évoluer l'interface, et voir qu'une classe doit écrire toutes les méthodes de l'interface.

Question 0, avec la formatrice

Copiez l'interface, le guerrier et le Main, et lancez le.

public interface Hero {
    String getName();
    int attack(); // renvoie les dégâts infligés
}
public class Warrior implements Hero {
    private final String name;
    private final int strength;

    public Warrior(String name, int strength) {
        this.name = name;
        this.strength = strength;
    }

    @Override public String getName() { return name; }
    // Le guerrier inflige sa force en dégâts.
    @Override public int attack() { return strength; }
}
Hero conan = new Warrior("Conan", 12);
System.out.println(conan.getName() + " inflige " + conan.attack() + " dégâts");

La consigne

  1. Créez Mage, qui implémente Hero, avec une intelligence : il inflige 2 fois son intelligence en dégâts.
  2. Créez Archer, qui implémente Hero, avec un nombre de flèches : il inflige 4 dégâts par flèche.
  3. Créez Team, qui a une List<Hero>, et les méthodes add(Hero), totalDamage(), strongest() et printAttacks().
  4. Dans le Main : Conan (force 12), Merlin (intelligence 9), Robin (5 flèches). L'équipe inflige 50 dégâts, et le plus fort est Robin.

reflexion.md :

  • Votre Team range un guerrier, un mage et un archer dans une seule List<Hero>. Pourquoi Java l'accepte-t-il ? Dans totalDamage(), comment Java sait-il quelle méthode attack() appeler ?
  • Relisez vos trois héros : getName() s'écrit de la même façon dans chacun, attack() jamais deux fois pareil. L'interface vous a-t-elle évité de recopier du code ? Qu'en concluez-vous ?

Étape 2 : les soins

Les héros vont maintenant pouvoir soigner l'équipe.

  1. Ajoutez dans l'interface Hero la méthode int heal();, qui renvoie les points de vie soignés. Lancez, et lisez les messages du compilateur.
  2. Écrivez heal() dans chaque héros : le mage soigne autant que son intelligence, le guerrier et l'archer ne soignent pas.
  3. Complétez printAttacks() pour afficher aussi les soins de chaque héros : Merlin inflige 18 dégâts et soigne 9 points de vie.
  4. Ajoutez dans Team deux méthodes : totalHealing(), la somme des soins de tous les héros, et bestHealer(), le héros qui soigne le plus. L'équipe soigne 9 points de vie, et le meilleur soigneur est Merlin.

reflexion.md :

  • Lorsque vous avez ajouté heal() dans l'interface, que s'est-il passé ? Pourquoi ?
  • Le guerrier et l'archer ne soignent pas. Pourquoi doivent-ils quand même écrire heal() ?

Étape 3 : un nouveau héros

Un prêtre rejoint l'équipe. Créez Priest, qui implémente Hero, avec une foi : il inflige sa foi en dégâts, et soigne 3 fois sa foi. Dans le Main, ajoutez Frère Tuck (foi 4) à l'équipe, et relancez : l'équipe inflige 54 dégâts, soigne 21 points de vie, et le meilleur soigneur est Frère Tuck. Notez ce que vous avez dû changer dans Team.

reflexion.md :

  • Vous avez ajouté un quatrième héros. Combien de lignes de Team avez-vous modifiées pour que totalDamage(), strongest() et bestHealer() en tiennent compte ? Pourquoi ?

Partie optionnelle

Ajoutez roundsToDefeat(int bossHealth) dans Team. bossHealth, ce sont les points de vie du boss : à chaque tour, tous les héros attaquent une fois, et les dégâts de l'équipe se retirent des points de vie du boss. Combien de tours faut-il à l'équipe complète pour vaincre un boss de 200 points de vie ?
